So the automated walk ends at login. The channel-verification step and the dashboard still need a manual pass in a real browser, or an allowlist for the test runner (see recommendations).

## Findings

### High
1. **The logged-in area is behind an interactive Cloudflare challenge.** The public pages (signup, login, thank-you) load cleanly, but the first page after login shows "Verify you are human". The cause could be bot scoring on a headless browser from a datacenter IP, which real users won't hit. But if this is a WAF rule on `/users/*`, it also adds friction at the most important onboarding step, right after login. Worth checking the Cloudflare security events for this ray (`a508cbc9d9d69acd`, 2026-10-26 ~10:33 UTC) to see which rule fired.

### Medium
2. **Thank-you page shows a large blank card area.** The page embeds an iframe pointing to `lottie.host/?file=b5e61140-…/mtd3mYAayB.json`, and that file returns **403**. Another lottie.host file returns 200 from the same network, so this one file has been removed or made private. Every new signup sees an empty box above "Thank You!". The same broken iframe is also on `/login`. Fix: re-host the animation (or use a static image) and drop the iframe.
3. **Unpinned third-party script on every auth page.** `/signup`, `/login` and `/thank-you` load `https://unpkg.com/@dotlottie/player-component@latest/…`. A breaking or compromised release ships to users straight away. Pin a version (or self-host) and add SRI.
4. **The website check rejects example-style URLs, but the error only appears after submit.** For real users that's fine, but the message shows up as a page-level notice and no field is highlighted. Inline validation on the URL field would save a round trip.

### Low
5. **Confirmation email is the Devise default.** The subject "Confirmation instructions" is generic and easy to miss or filter. Something like "Confirm your Cuelinks account" would be clearer. The footer still links Google+ (shut down in 2019) with icons from a `zingoy/mailer` Cloudinary path, and the "Terms of Site" link label is inconsistent with "Terms & Conditions" on the site.
6. **Footer copyright says "© 2024"** on the thank-you page (and site-wide footer).
7. **Console noise after login:** CSP blocks `data:,` fetches from the Cloudflare challenge script (`connect-src` violations). This is harmless, but it hides real errors in monitoring.
8. **Phone field format:** the field expects the bare 10-digit number with a separate country picker. Pasting `+91 …` isn't normalised client-side. Not tested whether the server rejects it; worth a quick check since users often paste numbers that way.

## Not covered (follow-up)
- Channel verification (`/users/edit`), dashboard, campaigns, link tools, payouts. Blocked by item 1.
- Mobile viewport (`signup.js --mobile`). Skipped to avoid creating a second test account until the Cloudflare block is resolved, since the mobile run would stop at the same point.
- Facebook / Google sign-up paths.

## Recommendations
1. Allowlist the test runner for QA (a Cloudflare WAF skip rule on a header or token only the runner sends), or run `journey.js` headed from an office IP. Then re-run `node journey.js runs/<dir>` to walk the dashboard.
2. Fix the broken lottie iframe on `/thank-you` and `/login`.
3. Pin `@dotlottie/player-component` to a fixed version.
